# Introduction

hclapi is a lightweight API engine distributed as a single binary and embeddable Go module. It turns HCL manifests into instant HTTP APIs, combining data access, validation, transformation, and route definitions in a single declarative runtime with zero-drift OpenAPI 3.1 generation.

:::info Request-time execution
Manifests are parsed and compiled once at boot time. hclapi executes pipelines dynamically per request without generating or compiling Go source.
:::

## How hclapi works

A route consists of an HTTP method and path pattern, optional request validation, and an ordered pipeline of steps:

1. An incoming request matches against a `route` block pattern (e.g. `POST /users/{id}`).
2. Path, query, header, and body data are validated against declared schema constraints, with valid scalar parameters coerced into native Go types (`int64`, `float64`, `bool`).
3. Pipeline steps (`sql`, `http`, `valkey`, `starlark`, `go`) run sequentially in declared order and write outputs into the request context.
4. A `respond` step terminates execution, applies schema egress masking, and streams the response.

See [Request lifecycle](/docs/concepts/lifecycle) for the execution model and [Pipelines and steps](/docs/concepts/pipelines) for pipeline rules.

## What hclapi is for

hclapi is intended for HTTP APIs where the service layer is primarily an interface over data storage and external services. It keeps route definitions, queries, input validation, and transformations together in readable HCL manifests.

hclapi doesn't replace general-purpose application frameworks for complex long-running worker loops, background job queues, or stateful streaming sessions.

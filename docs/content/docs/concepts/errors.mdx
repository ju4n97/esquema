# Errors and problem details

hclapi implements [RFC 9457 Problem Details for HTTP APIs](https://www.rfc-editor.org/rfc/rfc9457) for all error responses. Error payloads use the standard `application/problem+json` media type.

## Standard error payload

```json
{
  "type": "urn:hclapi:error:not-found",
  "title": "Not Found",
  "status": 404,
  "detail": "User not found"
}
```

| Field            | Type     | Description                                                   |
| :--------------- | :------- | :------------------------------------------------------------ |
| `type`           | `string` | URI identifier for the error type (`urn:hclapi:error:<slug>`) |
| `title`          | `string` | Short human-readable summary of the HTTP status code          |
| `status`         | `int`    | Standard HTTP status code integer                             |
| `detail`         | `string` | Explanation specific to this occurrence                       |
| `invalid_params` | `list`   | Field validation failures, present on HTTP 422 errors         |

## The `problem()` function

Use the built-in `problem(status, detail)` function inside `catch` blocks or conditional `respond` steps:

```hcl
# In SQL error catches
catch {
  code   = "23505"
  status = 409
  body   = problem(409, "An account with this email already exists")
}

# In conditional responses
respond {
  when   = steps.find_user.rows_affected == 0
  status = 404
  body   = problem(404, "User not found")
}
```

## Returning Problem Details from native Go handlers

If a native Go step handler returns an instance of `problem.Problem`, the runtime halts the pipeline and streams it directly to the client:

```go
func handlePayment(ctx context.Context, req *hclapi.GoRequest) (any, error) {
    if !hasSufficientBalance() {
        return nil, problem.New(http.StatusPaymentRequired, "Insufficient account balance")
    }
    return map[string]any{"status": "paid"}, nil
}
```

## Automatic runtime error responses

### Malformed JSON (HTTP 400)

```json
{
  "type": "urn:hclapi:error:bad-request",
  "title": "Bad Request",
  "status": 400,
  "detail": "Malformed JSON request body"
}
```

### Payload too large (HTTP 413)

```json
{
  "type": "urn:hclapi:error:request-entity-too-large",
  "title": "Request Entity Too Large",
  "status": 413,
  "detail": "request body exceeds limit of 10485760 bytes"
}
```

### Validation errors (HTTP 422)

Returned when incoming coordinates violate schema constraints. All failures return grouped inside `invalid_params`:

```json
{
  "type": "urn:hclapi:error:unprocessable-entity",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Request failed schema validation constraints",
  "invalid_params": [
    { "name": "body.email", "reason": "must be a valid email address" },
    { "name": "path.id", "reason": "must be an integer" }
  ]
}
```

### Unhandled step errors (HTTP 500)

```json
{
  "type": "urn:hclapi:error:internal-server-error",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "step \"query\": connection reset by peer"
}
```

### Recovered panics (HTTP 500)

When a Go handler or middleware encounters a panic, it is captured by the fault isolation boundary:

```json
{
  "type": "urn:hclapi:error:internal-server-error",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "step \"compute\" panic: runtime error: invalid memory address or nil pointer dereference"
}
```

### Gateway timeout (HTTP 504)

Returned when a client disconnects or an upstream context deadline is exceeded:

```json
{
  "type": "urn:hclapi:error:gateway-timeout",
  "title": "Gateway Timeout",
  "status": 504,
  "detail": "Client request canceled"
}
```

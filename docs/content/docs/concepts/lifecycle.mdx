# Request lifecycle

hclapi operates in two distinct phases. Manifests are verified once when the server boots, and incoming requests run through a fast, sequential execution pipeline.

| Phase       | Trigger              | Actions                                                                                             | On failure                                              |
| :---------- | :------------------- | :-------------------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| **Boot**    | `hclapi serve` boots | Discovers files, opens connection pools, precompiles Starlark scripts, and caches OpenAPI documents | Halts immediately with a clear terminal diagnostic      |
| **Request** | HTTP call arrives    | Enforces size limits, validates inputs, executes steps, and streams response                        | Returns an RFC 9457 error payload; server keeps running |

## Execution stages

Incoming HTTP Request

1. Telemetry and panic guard
   - Starts root trace timer and extracts W3C traceparent headers
   - Captures unexpected panics and converts them to RFC 9457 500 responses

2. Payload size enforcement
   - Reads the body through an io.LimitReader bounded by server.max_body_size
   - Halts immediately with HTTP 413 if the payload is too large

3. Ingress validation and type coercion
   - Validates path, query, header, and body data against schema constraints
   - Rejects invalid payloads with HTTP 422 or malformed JSON with HTTP 400
   - Coerces valid scalar path and query parameters into native int64, float64, and bool types

4. Context initialization
   - Builds the request-scoped ctx object holding input coordinates and timestamps

5. Sequential step execution
   - Runs declared steps (sql, http, valkey, starlark, go) one by one
   - Emits individual OpenTelemetry step spans and records step outputs into context

6. Respond and egress masking
   - Evaluates conditional when expressions to select matching response
   - Applies schema masks to prune undeclared fields
   - Streams JSON or raw non-JSON payloads based on Content-Type

# respond

The `respond` step terminates pipeline execution and streams the HTTP response. No subsequent step runs after a matching `respond` step triggers.

```hcl
respond {
  when   = steps.fetch.rows_affected == 0
  status = 404
  body   = problem(404, "User not found")
}

respond {
  status = 200
  schema = list(User)
  body   = steps.fetch.rows
}
```

## Attributes

| Attribute | Type   | Default | Description                                  |
| :-------- | :----- | :------ | :------------------------------------------- |
| `status`  | `int`  | `200`   | HTTP response status code                    |
| `headers` | `map`  | `{}`    | Static or dynamic HTTP response headers      |
| `body`    | `any`  | `null`  | Payload to serialize                         |
| `schema`  | `type` | `null`  | Named schema or `list(T)` for egress masking |
| `when`    | `bool` | `true`  | Conditional expression                       |

## Egress masking with schemas

When you specify a `schema` on a `respond` step, hclapi filters outbound payloads:

- Extra columns returned by database queries (like `password_hash` or internal tokens) are stripped.
- Only properties declared in the target schema model are serialized.

```hcl
# Single entity masking
respond {
  status = 200
  schema = User
  body   = steps.fetch_user.row
}

# Collection masking
respond {
  status = 200
  schema = list(User)
  body   = steps.list_users.rows
}
```

## Inline schema definition

You can define egress masking fields directly inline without creating a global schema model:

```hcl
respond {
  status = 201

  schema {
    field "message" {
      type = string
    }
    field "user" {
      type = User
    }
  }

  body = {
    message      = "User registered"
    secret_token = "dropped_by_mask"
    user         = steps.create.row
  }
}
```

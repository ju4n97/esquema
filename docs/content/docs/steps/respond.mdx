# respond

The `respond` step terminates pipeline execution and streams the HTTP response. No subsequent step runs after a matching `respond` step triggers.

```hcl
respond {
  when   = steps.fetch.rows_affected == 0
  status = 404
  body   = problem(404, "User not found")
}

respond {
  status = 200
  schema = "[]User"
  body   = steps.fetch.rows
}
```

## Attributes

| Attribute | Type     | Default | Description                               |
| :-------- | :------- | :------ | :---------------------------------------- |
| `status`  | `int`    | `200`   | HTTP response status code                 |
| `headers` | `map`    | `{}`    | Static or dynamic HTTP response headers   |
| `body`    | `any`    | `null`  | Payload to serialize                      |
| `schema`  | `string` | `""`    | Schema name used for egress field masking |
| `when`    | `bool`   | `true`  | Conditional expression                    |

## Streaming raw non-JSON payloads

If `headers` sets a non-JSON `Content-Type`, `respond` streams strings and byte slices directly without wrapping them in JSON quotes:

```hcl
respond {
  status = 200
  headers = {
    "Content-Type"        = "text/csv"
    "Content-Disposition" = "attachment; filename=\"report.csv\""
  }
  body = "id,name\n1,alice"
}
```

## Egress masking

When you declare a `schema` on a `respond` step, hclapi filters outbound payloads:

- Extra columns returned by database queries like `password_hash` or internal tokens are stripped.
- Only properties declared in the target schema are serialized.

Array schemas use the `[]` prefix:

```hcl
respond {
  status = 200
  schema = "[]User"
  body   = steps.list_users.rows
}
```

# sql

The `sql` step executes a prepared SQL statement against a declared database pool.

```hcl
step "sql" "create_user" {
  connection = "main"
  query      = <<-SQL
    INSERT INTO users (email, role)
    VALUES (@email, @role)
    RETURNING id, email, role
  SQL
  args = {
    email = ctx.request.body.email
    role  = "member"
  }
  catch "23505" {
    status = 409
    body   = problem(409, "User already registered")
  }
}
```

## Attributes

| Attribute        | Type     | Required | Description                                                      |
| :--------------- | :------- | :------: | :--------------------------------------------------------------- |
| `connection`     | `string` |   yes    | Connection pool name declared in `connection "sql"`              |
| `query`          | `string` |   yes    | SQL query or statement using `@param` placeholders               |
| `args`           | `map`    |    no    | Context values bound to `@param` placeholders                    |
| `when`           | `bool`   |    no    | Conditional expression; step is skipped if it evaluates to false |
| `catch "<code>"` | `block`  |    no    | Catches database error codes and halts the pipeline              |

## Exported outputs

| Field                        | Type    | Description                                       |
| :--------------------------- | :------ | :------------------------------------------------ |
| `steps.<name>.rows`          | `[]map` | All returned rows, or an empty list if none match |
| `steps.<name>.row`           | `map`   | The first returned row, or `null` if none match   |
| `steps.<name>.rows_affected` | `int`   | Rows returned, inserted, updated, or deleted      |

## Parameter binding

You don't need to change query placeholders between database engines. Write parameters using `@name`, and hclapi rewrites them automatically based on the connection's engine:

- **`postgres`**: Rewritten to `$1`, `$2`, etc.
- **`sqlserver`**: Rewritten to `@p1`, `@p2`, etc.
- **`sqlite` and `mysql`**: Rewritten to `?`.

The query rewriter uses single pass token parsing. It won't touch `@` characters inside string literals like `'admin@example.com'`, comments like `-- @todo`, or operators like `@>`.

## Catching database errors

If a query fails, hclapi checks matching `catch` blocks before returning a 500 error. When an error code matches, it halts the pipeline and returns the configured problem payload:

```hcl
catch "23505" {
  status = 409
  body   = problem(409, "An account with this email already exists")
}
```

### Common error codes

| Error condition           | PostgreSQL | SQLite |  MySQL   | SQL Server |
| :------------------------ | :--------: | :----: | :------: | :--------: |
| **Unique violation**      | `"23505"`  | `"19"` | `"1062"` |  `"2627"`  |
| **Foreign key violation** | `"23503"`  | `"19"` | `"1452"` |  `"547"`   |
| **Not null violation**    | `"23502"`  | `"19"` | `"1048"` |  `"515"`   |

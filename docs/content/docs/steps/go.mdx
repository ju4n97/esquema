# go

The `go` step calls a custom Go function registered on the engine. Use it when you need capabilities outside SQL and Starlark, such as calling custom SDKs or executing proprietary algorithms.

```hcl
step "go" "compute_tax" {
  use = "tax.calculate"
  args = {
    amount   = ctx.request.body.amount
    country  = ctx.request.headers.cf_ipcountry
    subtotal = steps.cart.result.total
  }
}
```

## Handler signature

Register handlers using the `hclapi.WithStep` option when initializing the engine:

```go
func(ctx context.Context, step *hclapi.Step) (any, error)
```

The `*hclapi.Step` struct exposes:

```go
type Step struct {
    Name    string
    Args    Args
    Request *http.Request
}
```

## Working with arguments

`step.Args` provides typed helpers with automatic coercion:

```go
func calculateTax(ctx context.Context, step *hclapi.Step) (any, error) {
    // Typed extraction with fallback
    amount := step.Args.GetOr("amount", 0.0)
    country := step.Args.GetOr("country", "CO")

    // Bind all arguments into a struct in one line
    var params TaxParams
    if err := step.Args.Bind(&params); err != nil {
        return nil, err
    }

    return map[string]any{"tax": amount * 0.20}, nil
}
```

## Fault isolation

Panics inside Go steps are caught by an internal boundary guard:

- The panic stacktrace is logged through `slog` with the request `trace_id` attached.
- The step's OpenTelemetry span is marked as an error.
- The client receives a clean RFC 9457 HTTP 500 Problem Details response without crashing the server.

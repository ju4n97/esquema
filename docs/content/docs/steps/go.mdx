# go

The `go` step calls a custom Go callback function registered on the runtime engine.

```hcl
go "compute_tax" {
  use = "tax.calculate"
  args = {
    amount   = ctx.request.body.amount
    country  = ctx.request.headers.cf_ipcountry
    subtotal = steps.cart.result.total
  }
}
```

## Handler signature

Register handlers using the `hclapi.WithStep` or `hclapi.WithGoHandler` option:

```go
func(ctx context.Context, in *hclapi.StepInput) (any, error)
```

The `*hclapi.StepInput` struct exposes:

```go
type StepInput struct {
    Name    string        // Step name declared in manifest
    Args    Args          // Evaluated arguments from HCL args map
    Request *http.Request // Raw standard *http.Request
}
```

## Working with arguments

`req.Args` provides typed helpers with automatic coercion:

```go
func calculateTax(ctx context.Context, in *hclapi.StepInput) (any, error) {
    // Typed extraction with fallback
    amount := in.Args.GetOr("amount", 0.0)
    country := in.Args.GetOr("country", "CO")

    // Bind all arguments into a destination struct
    var params TaxParams
    if err := in.Args.Bind(&params); err != nil {
        return nil, err
    }

    return map[string]any{"tax": amount * 0.20}, nil
}
```

## Fault isolation

Panics inside Go steps are caught by an internal boundary guard:

- The panic stacktrace is logged through `slog` with the request `trace_id` and `span_id` attached.
- The step's OpenTelemetry span is marked with `codes.Error`.
- The client receives RFC 9457 HTTP 500 Problem Details response without crashing the process.

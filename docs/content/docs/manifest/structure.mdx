# Files and structure

hclapi compiles its configuration from a single file, a folder, or glob patterns like `hclapi serve ./routes/**/*.hcl`.

## File discovery

When pointing hclapi at a directory, the loader recursively discovers all files ending in `.hcl`. Hidden files or directories starting with a dot (`.git`, `.vscode`) are automatically skipped.

## The .hclapiignore file

Place a `.hclapiignore` file in your root folder to ignore specific files or paths:

```text
# Skip temporary folders
scratch/

# Skip local overrides
local.hcl

# Skip drafts but keep preview
drafts/*
!drafts/preview.hcl
```

## Environment variables

Read environment variables during compilation or request execution using the `env` function:

```hcl
server {
  port = env("PORT", 8080)
}

connection "sql" "main" {
  engine = "postgres"
  source = env("DATABASE_URL", "postgres://localhost/main")
}
```

## Merging rules and invariants

hclapi merges manifests across all discovered files into a single runtime configuration:

1. **Singleton blocks**: The `server`, `openapi`, and `telemetry` blocks are singletons. Declaring `server` in more than one file halts boot with an error.
2. **Duplicate routes**: Endpoints are identified by method and path, such as `GET /users`. Declaring identical route patterns across manifests halts boot immediately.
3. **Shared namespace**: Connections and schemas share a single global namespace. A connection declared in `connections.hcl` is instantly accessible to routes in `routes/users.hcl`.

## Recommended project layout

```text
my-api/
├── .hclapiignore
├── server.hcl         # server {} and telemetry {}
├── connections.hcl    # connection pools
├── schemas/
│   └── user.hcl       # schema "User" {}
└── routes/
    ├── auth.hcl       # route "POST /auth" {}
    └── users.hcl      # route "GET /users" {}
```

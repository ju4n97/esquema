# telemetry

The `telemetry` block configures structured access logging, service names for tracing, and sensitive attribute redaction.

```hcl
telemetry {
  service_name = "store-api"

  logging {
    level  = "info"
    format = "json"
    redact = [
      "password",
      "authorization",
      "x-api-key",
      "credit_card"
    ]
  }
}
```

## Top level attributes

| Attribute      | Type     | Default | Description                                     |
| :------------- | :------- | :------ | :---------------------------------------------- |
| `service_name` | `string` | `""`    | Service identifier used in OpenTelemetry traces |

## Logging attributes

| Attribute | Type     | Default  | Description                                                    |
| :-------- | :------- | :------- | :------------------------------------------------------------- |
| `level`   | `string` | `"info"` | Minimum log level: `"debug"`, `"info"`, `"warn"`, or `"error"` |
| `format`  | `string` | `"text"` | Log encoding: `"json"` or `"text"`                             |
| `redact`  | `list`   | `[]`     | List of sensitive field names or headers to scrub              |

## Automatic field redaction

When keys matching the `redact` list appear in request headers or log entries, hclapi replaces their values with `"[REDACTED]"` before writing the log record:

```text
# Raw incoming header: Authorization: Bearer secret-token-xyz
# Emitted access log:
{"level":"INFO","msg":"http_request","path":"/users","headers":{"Authorization":"[REDACTED]"}}
```

Sensitive tokens won't leak into log aggregators like Loki or Datadog.

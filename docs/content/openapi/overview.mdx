# OpenAPI overview

hclapi inspects your manifests at boot to compile a strict **OpenAPI 3.1** specification.

You don't need to maintain separate YAML files, write code annotations, or run external generators. Your HCL manifest is the single source of truth for both runtime execution and API documentation.

There aren't any hidden routes. If a specification document or interactive viewer is exposed by your service, you declare it explicitly as a `route` block using a `spec` or `docs` step.

## Specification mapping

The compiler maps every manifest element directly into the OpenAPI 3.1 document tree:

| Manifest element                   | OpenAPI 3.1 mapping                                                 |
| :--------------------------------- | :------------------------------------------------------------------ |
| `route "POST /users/{id}"`         | `paths["/users/{id}"]["post"]`                                      |
| `summary = "..."`                  | `operation.summary`                                                 |
| `tag = "..."`                      | `operation.tags`                                                    |
| `request.path` fields              | Path parameters (`in: path`, `required: true`)                      |
| `request.query` fields             | Query parameters (`in: query`) with bounds and defaults             |
| `request.headers` fields           | Header parameters (`in: header`) with formats                       |
| `request.body = User`              | `requestBody.content["application/json"].schema` (`$ref`)           |
| `respond { schema = "User" }`      | Response `$ref` under HTTP 200                                      |
| `respond { schema = "[]User" }`    | Array response wrapping the target schema `$ref`                    |
| `step "sql" { catch "23505" ... }` | HTTP 409 response pointing to `#/components/schemas/ProblemDetails` |
| Schema validation rules            | Automatic HTTP 422 response pointing to `ProblemDetails`            |
| `hidden = true`                    | Excluded completely from the specification catalog                  |

## Catalog exclusion

Routes configured with a `docs` or `spec` step are automatically excluded from the generated operations catalog. This prevents internal documentation viewers from polluting client SDKs.

## Client SDK generation

Because hclapi produces strict OpenAPI 3.1 documents, you can feed exported specifications directly into modern code generators:

| Language            | Recommended tools                                 |
| :------------------ | :------------------------------------------------ |
| **TypeScript / JS** | `openapi-typescript`, `hey-api`, or `orval`       |
| **Python**          | `datamodel-code-generator` or `openapi-generator` |
| **Go**              | `oapi-codegen`                                    |
| **Rust**            | `progenitor`                                      |
